## 收录规则

正式题库收录76篇原站公开原文：牛客59、个人博客15、V2EX 1、LeetCode Discuss 1。均有2026首次发布日期依据，正文涉及C++、后端、基础设施、Agent或AI应用；跨岗帖子只抽取通用相关部分，不改变原岗位名称。

检索在2026-10-30进行，组合公司、方向、轮次和年份关键词，也从聚合索引发现原帖，再回原站核对。中间聚合页只用于发现，未替代原始来源：例如[Agent原帖线索表](https://blog.mlxb.cc/interview/agent-sources/)。检索无法覆盖全网、删除内容、登录后私密内容或未索引笔记。

正式收录须同时满足：

1. 能读到原站具体帖子正文，定位作者与原始链接；导航壳、搜索摘要和二手改写不够。
2. 原站首次发布日期在2026年，且不晚于检索截止日。正文完整面试日期与发帖日期分列。
3. 作者以面试经历/复盘形式描述具体轮次或过程；纯教学题单、招聘广告、营销汇总与未展开题目不作为单次面经。
4. 提取的具体问题在原文中有依据；原帖没写的题面、公司、数值和算法变式不补猜。

“真实”在这里是公开来源和内容可追溯，不是对作者实际经历的独立认证。即便原文包含答案，本库也重新核查机制，不直接将作者回答当标准答案。

## 年份怎样核验

牛客页面有些前端只显示“09-23”。本轮读取同页`__INITIAL_STATE__`中对应主帖的`createTime/createdAt`，将Unix毫秒时间转换为`Asia/Shanghai`，编辑时间另列。只读取主帖数据，不拿推荐区帖子或整页最新日期判断。

个人博客核对正文日期、文章元数据与明确带2026的标题；V2EX核对`article:published_time`；LeetCode核对标题下的完整年月日。档案公开年份依据与日期，机器索引保存在[index.json](index.json)。原帖正文只写月日时不补上“面试发生于2026”的确定说法。

AB02的页面元数据先于标题面试日，已在档案标明冲突；它只能证明有一篇2026发布的作者自述，不能据此证明精确面试日。仅“2026届”、网站页脚2026、搜索引擎抓取于2026、旧文编辑于2026均不通过年份规则。

## 题目怎样归并

按知识点归并相似问法，每题保留全部已核对出处。跨篇归并只表示同知识点出现，不表示所有细节在每篇中逐字相同。多问题组合保留原始关联，算法口述和手写不混称；缺少具体题面时不自行补一道常见题。

多个来源可能来自同一作者、同一场经历或不同轮次，不作为独立统计样本。公司频次排名、全网高频占比和面试命中率不在本库结论范围。

原帖特殊条件单列：例如ALG-022末尾不足K也反转、DB-030前五个不同工资档位、ALG-019的0..4到0..6。N19末尾其他匿名公司追问不归给字节；N49不同公司段落分开归属；客户端岗位只保留C++通用问题。

## 答案怎样设计

参考[Skylm808/interview-qa](https://github.com/Skylm808/interview-qa)的结论、原理、场景和追问组织方式，分类同时参考[peng-yq/the-way-to-find-a-job](https://github.com/peng-yq/the-way-to-find-a-job)。本库独立撰写以下分层内容：

| 层次 | 用途 |
| --- | --- |
| 参考答案 | 直接结论、关键机制与适用前提 |
| 详细展开 | 状态、数据结构、时序、不变量及故障取舍的逐步解释 |
| 追问示范 | 针对该题的教学追问与可练习口述的完整回应 |
| 怎么理解 | 因果关系、不变量、时序或简洁例子 |
| 面试怎么讲 | 可口述的回答顺序和示例，需换成自己的事实 |
| 追问与易错 | 并发、失败、边界、版本或常见误区 |

扩写共整理80组机制说明，按知识点用于相关题目，并给313题逐一设计追问回应；其中63题增加代码/表格/时序/数值推演。教学例子不作为“原面试官实际追问”的证据，也不改变原帖来源数量和原题边界。

语言、OS、网络及数据库答案优先链接标准草案、Linux man-pages、RFC和官方文档。场景与项目题属于设计建议，不冒充唯一标准答案；算法题由不变量、复杂度与边界推导，并用示例代码辅助部分难点。技术参考资料可早于2026，年份限制针对面经。

版本口径：C++问题区分语言保证和常见ABI；OS默认Linux并注明跨系统差异；数据库以MySQL8.4/InnoDB为主要参照；Redis关注版本差异；MCP传输以2025-11-25规范为参照。它们用于解释2026面经中的知识点，并不声称原面试公司部署了这些版本。

## 保存与维护

公开目录不转载完整原帖、站点脚本、IP信息或登录态。`.research/`保存本轮工作缓存与旧版备份，已加入忽略规则；正式目录只保留归并题、独立答案、公开昵称和来源元数据。外链以后可能变化，失效时应记录状态并重新核查，不能编造替代原文。

`python scripts/check_docs.py`校验题目唯一、来源存在、2026日期、四层答案、Markdown本地链接与锚点。结构检查不等于所有设计已经生产验证。算法示例的实际检查方式见[示例说明](../examples/README.md)。
